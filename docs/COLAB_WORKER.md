# Colab rendition handoff

Deploy the backend, UI and public/colab-worker.py together. Open Admin > Colab GPU and create a temporary connection key. This reserves future queued encoding work for Colab for 24 hours; the current local encode is not interrupted. Open a GPU Colab notebook, download the script from the admin page, paste it into one cell and run. Enter the direct HTTPS Yoru origin and temporary key privately. Run one notebook at a time.

The notebook requires a working NVENC GPU. It checks GPU decoding/scaling support on the actual source and falls back to CPU decoding/scaling if unavailable. Video uses NVENC p4 CQ26, audio uses AAC128k, and HLS uses 6-second segments with aligned forced keyframes. CQ26 is a different setting from software CRF22, so compare output appearance and size. No browser playback/quality/sync testing has been performed.

Yoru serves a verified local source to the authorized notebook. Returned rendition files are authenticated and hashed; playlists must use local segment references, be complete, match expected source rendition names and have comparable duration. A full handoff records normal Yoru rendition checkpoints. Yoru's worker then verifies the source and saved rendition hashes, encrypts the segments, transfers them to HF and performs existing remote verification. The master encryption key, HF credentials and Google refresh tokens are never sent to Colab. Plain source/rendition data temporarily exists on the Colab runtime; only authenticated HTTPS transports it.

The temporary key grants access to the shared admin processing queue, not to a single selected title. Keep it secret. Revoke after use. A 15-minute job lease is renewed every 15 seconds; if disconnected, the job remains reserved and can be reclaimed after expiration. Completed renditions can be reused only while the same Colab disk survives. A new runtime restarts rendition work. No promise of unattended continuous availability is made.

To return an episode to local processing, use Release Colab job in the upload queue, then Retry processing. Revoking the key disables reservation of new local jobs but does not automatically release existing Colab reservations. A Space rebuild may invalidate keys/leases and remove unfinished source/rendition files. Retry processing now restores missing sources from the original Drive import, while browser-upload sources need original-file selection. READY remote media remains intact.

Use a public direct hf.space website origin: private HF Space access walls prevent this worker from reaching the authenticated application API. Queued episodes are processed one at a time on the GPU, while the existing local worker handles downloads, encryption and transfers. This is opt-in external rendition processing, not additional CPU encoding threads.
